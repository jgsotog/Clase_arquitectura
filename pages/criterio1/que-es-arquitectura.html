Que es Arquitectura de Software

La arquitectura de software es la estructura o estructuras de un sistema, que comprende los componentes de software, las propiedades externamente visibles de esos componentes y las relaciones entre ellos. Es la base sobre la que se construye todo sistema de software.

Definiciones Formales

Segun IEEE 1471-2000

"La organizacion fundamental de un sistema representada en sus componentes, las relaciones entre ellos y con el ambiente, y los principios que guian su diseno y evolucion."

Segun Bass, Clements y Kazman

"La arquitectura de software de un programa o sistema de computacion es la estructura o estructuras del sistema, que comprende los elementos de software, las propiedades externamente visibles de esos elementos, y las relaciones entre ellos."

Segun Martin Fowler

"La arquitectura se refiere a las decisiones importantes, aquellas que son dificiles de cambiar. Son las decisiones que desearas haber tomado correctamente al principio de un proyecto."

Elementos que Componen una Arquitectura

Los componentes son las unidades fundamentales de software que encapsulan funcionalidad. Pueden ser modulos, clases, servicios, microservicios, paquetes o cualquier unidad de encapsulamiento que el sistema defina.


Cada componente tiene:

  • Una interfaz publica (lo que expone al exterior)
  • Una implementacion interna (detalles ocultos)
  • Responsabilidades bien definidas
  • Dependencias explicitas con otros componentes

Los conectores definen como se comunican los componentes. Determinan el mecanismo de interaccion entre las partes del sistema.


Tipos de conectores:

  • Llamadas a procedimiento / metodo
  • Eventos y mensajes
  • Datos compartidos en memoria
  • Protocolos de red (HTTP, TCP, gRPC)
  • Colas de mensajes (RabbitMQ, Kafka)

La configuracion describe como se organizan los componentes y conectores en una topologia especifica. Es el "mapa" del sistema que muestra que componente se conecta con cual y mediante que tipo de conector.

Las restricciones son las reglas y limitaciones que la arquitectura impone al diseno. Pueden ser tecnologicas, de negocio o de calidad.


Ejemplos:

  • "La capa de presentacion no debe acceder a la base de datos directamente"
  • "Todas las comunicaciones deben usar HTTPS"
  • "El tiempo de respuesta no debe superar 200ms"

Analogia: Arquitectura de Edificios vs Software

Asi como un arquitecto civil disena la estructura de un edificio antes de construirlo, un arquitecto de software disena la estructura del sistema antes de programarlo. La siguiente tabla muestra la correspondencia:

Arquitectura Civil Arquitectura de Software
Planos del edificio Diagramas de arquitectura (UML, C4)
Cimientos y estructuras de carga Frameworks y servicios base
Habitaciones y pisos Modulos, componentes y capas
Tuberias y cableado Conectores, APIs, protocolos
Normas de construccion Principios SOLID, patrones de diseno
Codigo de seguridad Requisitos no funcionales (rendimiento, seguridad)
