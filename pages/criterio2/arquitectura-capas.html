Tema 2.4

Arquitectura en Capas

La arquitectura en capas organiza los componentes del sistema en grupos horizontales (capas), donde cada capa tiene una responsabilidad bien definida. Las capas superiores dependen de las inferiores, pero nunca al reves. Este patron promueve la separacion de responsabilidades y facilita el mantenimiento del sistema.

Diagrama de Arquitectura en Capas

Diagrama - Arquitectura de 4 Capas (N-Tier)

Las Cuatro Capas Clasicas

Responsabilidad

Maneja la interfaz de usuario y la interaccion con el usuario final. Muestra informacion y recibe entradas. No contiene logica de negocio.

Componentes tipicos:

  • Paginas HTML / Plantillas
  • Controladores de vista
  • Formularios y validacion visual
  • Componentes de interfaz grafica

Regla: Solo se comunica con la capa de logica de negocio.

Responsabilidad

Contiene las reglas de negocio y la logica central de la aplicacion. Procesa las solicitudes de la capa de presentacion y coordina las operaciones con la capa de datos.

Componentes tipicos:

  • Servicios de dominio
  • Reglas de validacion de negocio
  • Calculos y transformaciones
  • Orquestacion de procesos

Responsabilidad

Abstrae el acceso a los datos persistentes. Traduce las operaciones de la logica de negocio en consultas al almacen de datos (SQL, API, archivos).

Componentes tipicos:

  • Repositorios (Patron Repository)
  • ORM (Object-Relational Mapping)
  • Objetos de acceso a datos (DAO)
  • Adaptadores de APIs externas

Responsabilidad

Almacena y gestiona los datos persistentes del sistema. Proporciona mecanismos de consulta, transaccion e integridad de datos.

Componentes tipicos:

  • Motor de base de datos (MySQL, PostgreSQL, MongoDB)
  • Esquemas y tablas
  • Procedimientos almacenados
  • Indices y vistas

Reglas Fundamentales

Regla 1: Dependencia descendente

Las capas superiores dependen de las inferiores, nunca al reves. La capa de datos no debe conocer la existencia de la capa de presentacion.

Regla 2: Comunicacion entre adyacentes

Cada capa solo se comunica con la capa inmediatamente inferior. La capa de presentacion no debe acceder directamente a la base de datos.

Regla 3: Encapsulamiento de capa

Los detalles internos de cada capa estan ocultos para las demas. Si cambiamos la implementacion de una capa, las otras no deberian verse afectadas.

Actividad del Estudiante

Ejercicio Practico

Disenar un sistema de tres capas con responsabilidades claras. Tome un sistema real (por ejemplo, una tienda en linea) y defina que componentes pertenecen a cada capa. Dibuje el diagrama y explique por que cada componente pertenece a esa capa especifica.
