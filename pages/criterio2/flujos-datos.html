Tema 2.1

Estilo de Flujos de Datos: Tuberias y Filtros

El estilo arquitectonico de flujos de datos organiza un sistema como una serie de transformaciones sobre datos de entrada. Los datos fluyen a traves de tuberias (pipes) que conectan filtros (filters), donde cada filtro realiza una transformacion independiente.

Concepto Fundamental

En el patron de tuberias y filtros, el sistema se descompone en una serie de componentes de procesamiento secuencial. Cada componente (filtro) tiene un conjunto de entradas y salidas. Un filtro lee flujos de datos en sus entradas y produce flujos de datos en sus salidas, aplicando una transformacion local e incremental a los datos de entrada.

Las tuberias son los conectores que transmiten las salidas de un filtro hacia las entradas del siguiente. Este patron permite reutilizar filtros en diferentes configuraciones y facilita la modificacion del sistema agregando, quitando o reordenando filtros.

Componentes del Patron

Un filtro es una unidad de procesamiento independiente que transforma datos. Cada filtro opera de forma aislada: no conoce la identidad ni la existencia de otros filtros en la cadena. Solo sabe que recibe datos de entrada y debe producir datos de salida.


Caracteristicas clave:

  • Procesamiento independiente y sin estado compartido
  • Entrada y salida bien definidas
  • Puede funcionar de manera incremental (no necesita toda la entrada)
  • Reutilizable en diferentes cadenas de procesamiento

La tuberia es el conector que transporta datos entre filtros. Actua como un canal de comunicacion unidireccional. En sistemas Unix, este concepto se materializa con el operador | (pipe) en la linea de comandos.


Caracteristicas clave:

  • Transmision unidireccional de datos
  • Puede incluir buffering para desacoplar velocidades
  • No transforma los datos, solo los transporta
  • Define la topologia del flujo

El origen de los datos que alimentan la cadena de filtros. Puede ser un archivo, un flujo de red, un sensor, una base de datos o cualquier componente que genere datos para ser procesados.

El destino final de los datos procesados. Es el punto donde se recolectan los resultados de toda la cadena de transformaciones. Puede ser una pantalla, un archivo de salida, una base de datos o un sistema externo.

Ventajas y Desventajas

Reutilizacion de componentes

Los filtros se pueden reutilizar en diferentes cadenas de procesamiento sin modificaciones.

Facilidad de mantenimiento

Se pueden agregar, quitar o reordenar filtros sin afectar a los demas componentes.

Procesamiento concurrente

Los filtros pueden ejecutarse en paralelo si el hardware lo permite, mejorando el rendimiento.

Independencia de filtros

Cada filtro opera de forma aislada, lo que facilita las pruebas unitarias y la depuracion.

Sobrecarga por transformacion

El costo de serializar y deserializar datos entre filtros puede ser significativo.

Dificultad en interacciones complejas

No es adecuado para sistemas que requieren retroalimentacion o interaccion bidireccional entre componentes.

Latencia acumulada

Si los filtros son secuenciales, la latencia total es la suma de las latencias individuales.

Procesamiento de texto y datos

ETL (Extract, Transform, Load), compiladores, procesamiento de imagenes, audio y video.

Flujos de trabajo lineales

Cuando los datos siguen un camino lineal de transformaciones sin necesidad de retroalimentacion.
